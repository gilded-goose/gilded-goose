# Claims ledger

Every number or factual claim a judge can see (on screen, in the README, on Devpost, or said in the video) has a row
here. `node scripts/check-claims.ts`, part of `pnpm check`, re-reads each one from its source and
fails on any mismatch, in three ways:

- **Value:** the row's probe (in `scripts/check-claims.ts`, one per id) must print exactly the row's Value.
- **Shown:** the Claim text must appear, as written, in every file listed under "Shows in". If a line is reworded
  there, this row is reworded with it, or the check fails.
- **Placeholders stay placeholders:** a row whose Value is `placeholder` has no number yet. Its bracketed text must
  still be in each file, so nobody can swap in a guessed number. Before Nov 9 it gets a real count and a probe, or its line is cut.

A probe with no row, or a row with no probe, also fails.

**Reading the Source column.** We built Goose with a team of Claude agents, and a Source often names the one that did
the work: "Track" and a letter (Track C, Track P, ...) is one agent's line of work, "Lead" and a number is the agent
that led the team that day, "the DD" is the design reviewer and "Q" is the safety reviewer. Joshua directs them. "Our build notes", "our prior-art notes" and "his message" are private notes the public repo leaves out;
the row's probe never needs them, because it re-reads the public code, file or page the row names.

Two more rules run in the same check (Joshua's mandate, Fri Oct 30 2:40 PM, item 5; `scripts/claims-placeholders.ts`,
tested in `core/test/claims-placeholders.test.ts`):
- **The team:** the README, the Devpost text and the video credits (`docs/video-shot-list.md`) each say exactly "Joshua
  Javier and Lucas (a team of two)", and nothing else there names the team or its size. The old "[Joshua fills in]" is
  gone everywhere.
- **The links:** "[placeholder: video link" stays in the README and the Devpost text, with no link on its line, until the
  video link is due (Wed Nov 11). The repo link was filled when the repo went public (Wed Nov 11). Filling one means
  editing that list in the same commit.

Row ids: the rows above the first prefixed one predate the tracks. Each track appends its own rows with its prefix
(`c-` Trust & Content, `h-` Haggle, `s1-`, `s2-`, `d-`, `l-`, `v-`, …) and never edits another track's rows.
